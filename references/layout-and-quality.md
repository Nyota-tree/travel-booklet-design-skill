# Layout and quality patterns

Use these patterns when making a visual or printable booklet. They are defaults to adapt, not a required page count, aesthetic, or software stack.

## Format and hierarchy

- Choose a readable single-page format first. If the user wants a folded booklet, provide both a reading-order file and a correctly imposed print file when tools permit. A5 pages on landscape A4 sheets are one useful option; saddle-stitched page counts must be divisible by four.
- Keep margins large enough for trimming and binding. Use a consistent header (day/date/place), a clear title, and a modest divider. Let the local destination name outrank its translation, address, time, and notes.
- A compact route card can hold number, local name, translation/purpose, address, time, and NEXT. Put a verified recognition photo beside the corresponding card, not on an unrelated page. When a day has many stops, reduce card height or split the day; do not omit the next destination.
- A useful visual baseline is deep green `#0D4E49`, dark ink `#232421`, pale green `#EAF2EF`, warm neutral `#F3F0E9`, muted gray `#77756E`, and restrained orange `#B75B39`. Change the palette if the destination or accessibility needs call for it. Contrast and legibility matter more than matching these exact colors.
- Test body text, addresses, map legends, and translated signs at actual print size. Prefer fewer words or a page break over shrinking operational text until it is unreadable.

## Images and maps

- Use a full-width image mainly when it is a route map, a key geographic overview, or a deliberate section opener. Ordinary travel segments can use a narrow orientation strip plus paired stop photos. Do not repeat the same route as a full-page image and again on the following page.
- Keep storefront sign, doorway, and enough surroundings inside the crop. Record the source and branch match outside the final page if source credits would clutter the guide. Respect the user's requested image rights or attribution requirements.
- A map should include a real basemap where feasible, visible place labels, numbered stops, a legend in the traveler's language, and attribution. Mark simplified straight connections as visit order rather than walking/driving directions. If only a schematic is possible, label it accordingly.
- Avoid duplicated imagery, generic AI stock scenes masquerading as real locations, and photo-only pages that contain less useful information than the available space can hold.

## Tickets and service panels

- Put tickets close to the relevant day, preferably with key traveler-language notes about inspection, entrance, timing, and ID. Fit multiple tickets on one page only while all QR quiet zones and required printed fields remain fully visible; scan-test if possible.
- Use concise practical panels for local signage, pronunciation, station finding, rentals, supplies, or turnaround decisions. The panel background must cover all its text. Do not print production prompts or layout instructions in the traveler's booklet.

## Final review

Check every day from first stop through the last NEXT/END, including page transitions. Compare map numbers with stop numbers, photo identity with branch/address, and booking facts with source documents. Render or preview all pages, then inspect particularly dense pages, ticket crops, maps, front/back imposition, and long local names. Record uncertainties without disguising them as complete facts.
